# OpenVPN между площадками через VDS

В репозитории есть два скрипта для OpenVPN over UDP в режиме TUN:

1. `deploy-openvpn.py` устанавливает и настраивает OpenVPN-хаб на Ubuntu VDS.
2. `ovpn_to_rsc.py` преобразует клиентский `.ovpn`-профиль в RouterOS `.rsc` для MikroTik.

Схема по умолчанию:

```text
MikroTik A: 192.168.10.0/24
       │ OpenVPN UDP/TUN
       ▼
VDS: маршрутизация между площадками, без NAT
       ▲
       │ OpenVPN UDP/TUN
MikroTik B: 192.168.20.0/24
```

Сети площадок должны быть разными и не пересекаться с адресами VPN-туннеля `10.77.0.0/24`.

## 1. Развернуть OpenVPN на VDS

Скопируйте `deploy-openvpn.py` на VDS с Ubuntu и запустите от root:

```bash
sudo python3 deploy-openvpn.py
```

Скрипт запросит:

- LAN MikroTik A и LAN MikroTik B (по умолчанию `192.168.10.0/24` и `192.168.20.0/24`);
- публичный IPv4 или DNS-имя VDS;
- UDP-порт OpenVPN (по умолчанию `1194`);
- подтверждение перед установкой.

Затем он устанавливает `openvpn` и `easy-rsa`, создаёт CA и сертификаты сервера и двух клиентов, настраивает OpenVPN TUN, включает IPv4 forwarding и запускает systemd-службу. При существующей CA/PKI ключи не пересоздаются. Перезаписываемые конфигурации сохраняются в резервные копии с временной меткой.

Также создаётся отдельный сертификат Windows-клиента. Он получает адрес `10.77.0.4` и маршруты к обеим LAN. Для MikroTik зарезервированы `10.77.0.2` и `10.77.0.3`; адреса динамических VPN-клиентов выдаются начиная с `10.77.0.10`, чтобы не пересекаться со статическими адресами. Клиентские профили создаются в каталоге, доступном только root:

```text
/root/openvpn-clients/mikrotik-a.ovpn
/root/openvpn-clients/mikrotik-b.ovpn
/root/openvpn-clients/windows.ovpn
```

Профили содержат приватные ключи. Передавайте их только по защищённому каналу и не публикуйте.

Если UFW активен, скрипт разрешает входящий UDP-порт OpenVPN и пересылку трафика между двумя LAN, а также между VPN-клиентами и этими LAN. В противном случае правила нужно настроить в используемом firewall вручную. UDP-порт также необходимо разрешить в firewall панели хостинг-провайдера.

Проверка службы и подключений:

```bash
sudo systemctl status openvpn-server@server
sudo cat /var/log/openvpn-status-server.log
```

Если в системе используется другой systemd unit, скрипт выбирает обнаруженный шаблон службы, а точное имя выводит после настройки.

### Подключить Windows-клиент

Безопасно скопируйте `windows.ovpn` на Windows-компьютер и импортируйте профиль в OpenVPN Connect или OpenVPN GUI. Профиль содержит клиентский приватный ключ. При успешном подключении Windows получит доступ к маршрутам `192.168.10.0/24` и `192.168.20.0/24` (либо к сетям, указанным при установке).

Чтобы устройства Windows-клиента и обеих LAN могли обмениваться трафиком, сначала настройте соответствующие MikroTik с помощью `.rsc`, созданного конвертером ниже. Он добавляет исключения NAT и правила forwarding между локальной LAN роутера и VPN-подсетью `10.77.0.0/24`.

## 2. Создать RouterOS-скрипт для MikroTik

Запустите конвертер на компьютере, где доступен соответствующий `.ovpn`-профиль.

Для MikroTik A:

```bash
python3 ovpn_to_rsc.py mikrotik-a.ovpn --site a
```

Для MikroTik B:

```bash
python3 ovpn_to_rsc.py mikrotik-b.ovpn --site b
```

По умолчанию конвертер создаёт `.rsc` рядом с `.ovpn`. В `.rsc` будут команды для встроенного импорта OVPN-профиля, настройки интерфейса, маршрутов к удалённой LAN и VPN-подсети, исключений source NAT и правил forwarding между локальной LAN и удалённой LAN, а также Windows-клиентами в VPN-подсети.

Конвертер проверяет, что профиль содержит ровно один `remote`, использует UDP/IPv4 и TUN, а сертификаты и ключ находятся во встроенных блоках `<ca>`, `<cert>` и `<key>`. TCP, TAP, несколько `remote` и отдельные файлы сертификатов не поддерживаются.

Дополнительные параметры:

```bash
python3 ovpn_to_rsc.py mikrotik-a.ovpn --site a \
  --output mikrotik-a.rsc \
  --local-network 192.168.10.0/24 \
  --remote-network 192.168.20.0/24 \
  --interface ovpn-vds-a
```

Если профиль содержит директиву `auth-user-pass`, при отсутствии `--password` конвертер запросит пароль интерактивно. Не передавайте секрет через `--password` в командной строке, если историю команд или список процессов могут увидеть другие пользователи. При явном `--password` пароль будет записан в `.rsc`. Сгенерированные файлы конвертер создаёт с ограниченными правами доступа; существующие файлы он не перезаписывает без `--force`.

## 3. Импортировать конфигурацию на MikroTik

Для OpenVPN-клиента по UDP требуется RouterOS 7.17 или новее. Для каждой площадки загрузите на соответствующий роутер оба файла — `.ovpn` и созданный `.rsc` — в раздел **Files**, затем в терминале RouterOS выполните, подставив имя своего файла:

```routeros
/import file-name=mikrotik-a.rsc
```

На MikroTik B импортируйте `mikrotik-b.rsc`. Если LAN-сети отличаются от значений по умолчанию, укажите фактические сети через `--local-network` и `--remote-network`.

После импорта проверьте состояние интерфейса OVPN и таблицу маршрутизации. Для связи устройств между LAN должны быть подключены оба MikroTik; один роутер позволяет проверить только подключение к VDS.

## Ограничения и безопасность

- Оба скрипта предназначены для одного хаба и двух площадок с непересекающимися IPv4 LAN.
- Настройка маршрутов и firewall на стороне MikroTik выполняется сгенерированным `.rsc`; существующие правила firewall и маршрутизацию всё равно следует проверить перед применением.
- В конфигурации не добавляются правила NAT для трафика между LAN.
- `.ovpn` содержит приватный ключ клиента, а `.rsc` может содержать пароль аутентификации. Храните и передавайте их как секреты.
- Встроенный импорт `.ovpn` в RouterOS выполняет сам роутер; генератор не подключается к MikroTik и не может проверить результат импорта или доступность площадок.
